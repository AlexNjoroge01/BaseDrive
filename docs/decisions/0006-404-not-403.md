# 6. Unauthorized returns 404, not 403

**Status:** accepted

## Context
Item ids appear in URLs and share links. A 403 for "exists but not yours" lets anyone probe which ids exist.

## Decision
If the caller has **no** role on an item (no ownership, grant, or valid link on it or any ancestor), every route returns 404 with the same message as a missing item: "This item doesn't exist or you don't have access." A 403 is returned only when the caller *can* see the item but lacks the role for the action (e.g. a viewer trying to rename). That leaks nothing new.

## Consequences
- The UI shows one not-found state for both cases.
- Share-link scope is enforced the same way: a link to folder A returns 404 for anything outside A's subtree.
